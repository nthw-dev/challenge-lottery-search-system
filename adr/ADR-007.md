# ADR-007: Deploy on PostgreSQL 17

Status: Accepted · Date: 2026-09-05 · Relates to: design doc §6.4

## Context

All primary measurements were taken on PostgreSQL 16.13. Version 17 changes sequential-scan I/O,
write-ahead-log contention and B-tree array handling, any of which could move the numbers. The suite
was re-run on 17.11 under identical conditions: same dataset, same pod profile, same scripts.

## Decision

Recommend PostgreSQL 17 for deployment. Keep the design document's primary tables as measured on 16
so every number has one provenance, and present 17 as the measured improvement on top.

## Alternatives

- **Stay on 16** — nothing breaks, but it leaves a free 25 % latency improvement unused.
- **Restate every figure for 17** — would mix provenance; the full seven-scenario suite ran on 16.

## Consequences

Strategy C search: p95 55.8 → 41.9 ms, throughput 5,346 → 5,952 req/s, with no code change.
Allocation under contention: p95 73.8 → 68.0 ms, still zero duplicates. Nothing structural changes:
the strategy ranking is identical and the baseline still fails 96 % of requests under load despite
its single queries running up to 83 % faster. The "faster than baseline" multiple shrinks from about
17,000× to about 11,700× because 17 speeds the baseline up more than it speeds up C; the document
states it as four orders of magnitude on either version.
